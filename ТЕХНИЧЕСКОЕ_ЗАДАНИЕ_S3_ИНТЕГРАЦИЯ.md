## 2. Цели и задачи

### 2.1 Бизнес-цели

1. **Централизованное хранение данных о фильмах** - использование Yandex Cloud Object Storage как источника истины для каталога фильмов
2. **Оптимизация доставки контента** - хранение постеров в S3 с CDN-доступом
3. **Масштабируемость** - возможность добавления тысяч фильмов без изменения архитектуры
4. **Отказоустойчивость** - fallback-механизм для загрузки постеров

### 2.2 Технические задачи

| ID | Задача | Приоритет |
|----|--------|-----------|
| T1 | Разработать расширенную схему данных для хранения всех полей из JSON | Высокий |
| T2 | Реализовать S3-клиент для работы с Yandex Cloud Object Storage | Высокий |
| T3 | Создать скрипт синхронизации БД из JSON-файлов в бакете | Высокий |
| T4 | Реализовать механизм загрузки постеров с fallback | Средний |
| T5 | Добавить API-эндпоинт для получения постеров | Средний |
| T6 | Реализовать административный интерфейс синхронизации | Низкий |

## 3. Описание текущего состояния

### 3.1 Текущая схема данных фильмов

```typescript
// shared/schema.ts - текущая схема
export const movies = pgTable("movies", {
  id: varchar("id").primaryKey(),
  title: text("title").notNull(),
  titleEn: text("title_en"),
  year: integer("year").notNull(),
  posterUrl: text("poster_url"),
  backdropUrl: text("backdrop_url"),
  synopsis: text("synopsis"),
  synopsisEn: text("synopsis_en"),
  genres: text("genres").array(),
  director: text("director"),
  cast: text("cast").array(),
  runtime: integer("runtime"),
  rating: real("rating"),
  voteCount: integer("vote_count").default(0),
  createdAt: timestamp("created_at").defaultNow(),
});
```

### 3.2 Ограничения текущей схемы

1. Отсутствуют поля: страна, сценарист, продюсер, оператор, композитор, бюджет, сборы
2. Нет связи с внешним идентификатором (fid) из Кинопоиска
3. Постеры загружаются только по внешним URL
4. Нет механизма синхронизации с внешними источниками

### 3.3 Структура данных в S3 бакете

```
bucket/
├── 1000443.json    # Метаданные фильма "Балканский рубеж"
├── 1000443.jpg     # Постер фильма
├── 1047883.json    # Метаданные другого фильма
├── 1047883.jpg     # Постер
└── ...
```

## 6. Схема данных

### 6.1 Новая схема таблицы movies

**ВАЖНО:** Primary key таблицы movies - поле `fid` (идентификатор фильма из Кинопоиска). Старое поле `id` (UUID) удаляется.

```typescript
// shared/schema.ts - расширенная схема
export const movies = pgTable("movies", {
  // Основной идентификатор (Primary Key)
  fid: varchar("fid").primaryKey(),                // Kinopoisk Film ID (PRIMARY KEY)
  kinopoiskUrl: text("kinopoisk_url"),             // URL на Кинопоиске
  
  // Основная информация
  title: text("title").notNull(),                  // Название (русское)
  titleEn: text("title_en"),                       // Название (английское)
  year: integer("year").notNull(),                 // Год выпуска
  synopsis: text("synopsis"),                      // Описание
  synopsisEn: text("synopsis_en"),                 // Описание (английское)
  slogan: text("slogan"),                          // Слоган фильма
  
  // Классификация
  genres: text("genres").array(),                  // Жанры
  country: text("country"),                        // Страна производства
  ageRating: text("age_rating"),                   // Возрастной рейтинг (18+, 16+, etc.)
  
  // Создатели
  director: text("director"),                      // Режиссёр
  screenplay: text("screenplay"),                  // Сценарий
  producer: text("producer"),                      // Продюсер
  cinematographer: text("cinematographer"),        // Оператор
  composer: text("composer"),                      // Композитор
  artDirector: text("art_director"),               // Художник
  editor: text("editor"),                          // Монтаж
  cast: text("cast").array(),                      // Актёрский состав
  
  // Технические характеристики
  runtime: integer("runtime"),                     // Длительность (минуты)
  durationText: text("duration_text"),             // Длительность (текст: "2 ч 31 мин")
  
  // Рейтинги и статистика
  rating: real("rating"),                          // Рейтинг Кинопоиска
  voteCount: integer("vote_count").default(0),     // Количество голосов
  votesCountText: text("votes_count_text"),        // Текст ("497 003 оценки")
  
  // Финансы
  budget: text("budget"),                          // Бюджет
  boxOffice: text("box_office"),                   // Мировые сборы
  
  // Даты
  premiereRussia: text("premiere_russia"),         // Премьера в России
  premiereWorld: text("premiere_world"),           // Мировая премьера
  
  // Медиа
  posterUrl: text("poster_url"),                   // URL постера (fallback)
  s3PosterKey: text("s3_poster_key"),              // Ключ постера в S3 ({fid}.jpg)
  backdropUrl: text("backdrop_url"),               // URL фона
  
  // Метаданные
  parsedAt: timestamp("parsed_at"),                // Дата парсинга источника
  createdAt: timestamp("created_at").defaultNow(), // Дата создания в БД
  updatedAt: timestamp("updated_at").defaultNow(), // Дата обновления в БД
});
```

### 6.3 Миграция базы данных

**ВАЖНО:** Таблица movies пересоздаётся с новой структурой. Primary Key меняется с `id` (UUID) на `fid` (Kinopoisk ID). Старые данные удалены (15 фильмов).

```sql
-- Миграция: пересоздание таблицы movies с fid как PRIMARY KEY
-- Предварительно: DELETE FROM movies; (выполнено)

DROP TABLE IF EXISTS movies CASCADE;

CREATE TABLE movies (
  fid VARCHAR PRIMARY KEY,                          -- Kinopoisk Film ID (PRIMARY KEY)
  kinopoisk_url TEXT,
  title TEXT NOT NULL,
  title_en TEXT,
  year INTEGER NOT NULL,
  synopsis TEXT,
  synopsis_en TEXT,
  slogan TEXT,
  genres TEXT[],
  country TEXT,
  age_rating TEXT,
```

## 8. Скрипт синхронизации

### 8.1 Архитектура скрипта

```typescript
// scripts/sync-movies.ts

interface SyncOptions {
  mode: 'full' | 'incremental';
  dryRun: boolean;
  batchSize: number;
  concurrency: number;
}

interface SyncResult {
  processed: number;
  created: number;
  updated: number;
  skipped: number;
  errors: MovieSyncError[];
  duration: number;
}

interface MovieSyncError {
  fid: string;
  error: string;
  timestamp: Date;
}

class MovieSyncService {
  private s3Client: S3Client;
  private storage: IStorage;
  
  async sync(options: SyncOptions): Promise<SyncResult>;
  private async listJsonFiles(): Promise<string[]>;
  private async downloadAndParse(key: string): Promise<MovieJson>;
  private async checkPosterExists(fid: string): Promise<boolean>;
  private async upsertMovie(data: MovieJson): Promise<'created' | 'updated' | 'skipped'>;
  private mapJsonToMovie(json: MovieJson): InsertMovie;
}
```

### 8.2 Алгоритм синхронизации

```
1. INITIALIZE
   - Connect to S3
   - Connect to Database
   - Load existing movies (fid → updatedAt map)

2. LIST FILES
   - Get all *.json files from bucket
   - Filter by modification date (incremental mode)

3. FOR EACH JSON FILE (parallel, max 5):
   a. Download JSON content
   b. Parse and validate JSON
   c. Check if poster {fid}.jpg exists in S3
   d. Map JSON fields to database schema
   e. UPSERT to database:
      - IF fid not exists → INSERT
      - IF fid exists AND parsed_at > updatedAt → UPDATE
      - ELSE → SKIP
   f. Log result

4. FINALIZE
   - Generate summary report
   - Log total statistics
   - Close connections
```

### 8.3 Пример использования

```bash
# Полная синхронизация
npx tsx scripts/sync-movies.ts --mode=full

# Инкрементальная синхронизация
npx tsx scripts/sync-movies.ts --mode=incremental

# Тестовый прогон (без записи в БД)
npx tsx scripts/sync-movies.ts --mode=full --dry-run
```

## 9. Механизм загрузки постеров

### 9.1 Сервис загрузки постеров

```typescript
// server/poster-service.ts

interface PosterResult {
  url: string;
  source: 's3' | 'fallback' | 'placeholder';
  expiresAt: Date | null;
}

class PosterService {
  private s3Client: S3Client;
  private urlCache: Map<string, { url: string; expiresAt: Date }>;
  
  async getPosterUrl(movie: Movie): Promise<PosterResult> {
    // 1. Check cache
    const cached = this.urlCache.get(movie.id);
    if (cached && cached.expiresAt > new Date()) {
      return { url: cached.url, source: 's3', expiresAt: cached.expiresAt };
    }
    
    // 2. Try S3 presigned URL
    if (movie.s3PosterKey) {
      try {
        const url = await this.generatePresignedUrl(movie.s3PosterKey);
        const expiresAt = new Date(Date.now() + 3600 * 1000);
        this.urlCache.set(movie.id, { url, expiresAt });
        return { url, source: 's3', expiresAt };
      } catch (error) {
        console.warn(`S3 poster not available for ${movie.id}:`, error);
      }
    }
    
    // 3. Fallback to poster_url
    if (movie.posterUrl) {
      return { url: movie.posterUrl, source: 'fallback', expiresAt: null };
    }
    
    // 4. Return placeholder
    return { 
      url: '/images/poster-placeholder.jpg', 
      source: 'placeholder', 
      expiresAt: null 
    };
  }
  
  private async generatePresignedUrl(key: string): Promise<string> {
    return this.s3Client.generatePresignedUrl('getObject', {
      Bucket: config.s3.bucket,
      Key: key,
      ExpiresIn: config.presignedUrl.expiresIn,
    });
  }
}
```

### 9.2 Использование на фронтенде

```typescript
// client/src/hooks/usePosterUrl.ts

  const { data, isLoading } = useQuery({
```

## 10. Обработка ошибок

### 10.1 Классы ошибок

```typescript
// server/errors/s3-errors.ts

export class S3ConnectionError extends Error {
  constructor(message: string) {
    super(`S3 Connection Error: ${message}`);
    this.name = 'S3ConnectionError';
  }
}

export class S3ObjectNotFoundError extends Error {
  constructor(key: string) {
    super(`S3 Object Not Found: ${key}`);
    this.name = 'S3ObjectNotFoundError';
  }
}

export class MovieSyncError extends Error {
  constructor(
    public fid: string,
    public originalError: Error
  ) {
    super(`Failed to sync movie ${fid}: ${originalError.message}`);
    this.name = 'MovieSyncError';
  }
}

export class InvalidMovieJsonError extends Error {
  constructor(fid: string, reason: string) {
    super(`Invalid movie JSON for ${fid}: ${reason}`);
    this.name = 'InvalidMovieJsonError';
  }
}
```

### 10.2 Стратегия обработки

| Ошибка | Действие | Fallback |
|--------|----------|----------|
| S3 недоступен | Логировать, использовать кэш | Показывать poster_url |
| JSON невалидный | Пропустить фильм, логировать | Продолжить синхронизацию |
| Постер отсутствует | Использовать poster_url | Показать placeholder |
| БД недоступна | Прервать синхронизацию | — |
| Timeout | Retry 3 раза с exponential backoff | Пропустить |
