# CineFeels — функциональность и архитектура

*Актуализировано по коду проекта: 24 сентября 2026 года. Описано то, что реализовано в репозитории, а не гарантированное состояние внешних сервисов или развёрнутой версии.*

## 1. Что делает система

CineFeels — русскоязычное веб-приложение для поиска фильмов, выставления оценок и получения рекомендаций. Основные пользовательские сценарии:

| Сценарий | Реализация |
|---|---|
| Каталог | Главная показывает популярные и недавно добавленные фильмы; API выдаёт также фильм дня/подборку, жанры и кандидатов для оценки. |
| Карточка фильма | Название, описание, жанры, участники, рейтинг, постер, ссылка на Кинопоиск, похожие фильмы. Авторизованный пользователь может поставить оценку, добавить фильм в «Посмотреть позже» или избранное. |
| Поиск | Страница поиска отправляет текст запроса и жанры; по умолчанию используется семантический поиск. API также поддерживает быстрый поиск по названию (`searchMode: "text"`), фильтры по году/рейтингу и диагностический ответ. |
| Быстрые рекомендации без аккаунта | QuickRating на главной предлагает оценивать фильмы по шкале 1–10; после **5 оценок в интерфейсе** запрашивает рекомендации. Оценки хранятся в `localStorage` 24 часа, без записи в учётную запись. API принимает от 3 до 20 оценок. |
| Рекомендации для пользователя | По сохранённым оценкам: EASE, затем при необходимости локальный рекомендатель SVD и жанровый алгоритм; при отсутствии оценок — популярные фильмы. |
| Учётная запись | Вход и регистрация доступны на вкладках страницы `/login`; сервер поддерживает выход и получение текущего пользователя. Профиль показывает статистику, историю оценок и рекомендации. |
| Объяснения ИИ | При настроенном YandexGPT сервер может дополнять поиск и рекомендации текстовыми объяснениями. Без него основные ответы API остаются доступны. |

Оговорки по пользовательскому интерфейсу: главная страница запрашивает `/api/user`, тогда как фактический маршрут проверки сессии — `/api/auth/me`. Из-за этого персональный блок на главной может не появляться даже после входа. Страница поиска не передаёт переключатель режима в компонент поиска и фактически всегда вызывает семантический режим; текстовый режим используется в QuickRating.

## 2. Технологический стек

| Слой | Технологии и назначение |
|---|---|
| Фронтенд | React 18, TypeScript, Vite; SPA-маршрутизация Wouter; запросы и кэш TanStack Query; Tailwind CSS, Radix UI / компоненты в стиле shadcn, Lucide; светлая и тёмная темы. Используются также React Hook Form и Zod. |
| Основной сервер | Node.js, TypeScript, Express 4; JSON REST API; в разработке сервер подключает Vite, в production отдаёт собранные статические файлы. |
| Авторизация | Passport Local + `express-session`, пароли хешируются с солью через scrypt, идентификатор пользователя хранится в сессии/cookie. |
| Реляционные данные | PostgreSQL через `pg` Pool, Drizzle ORM и общие TypeScript-схемы в `shared/schema.ts`; для отдельных входных данных используется `drizzle-zod`/Zod. |
| Рекомендательная модель | Python 3.11+, FastAPI/Uvicorn, NumPy/SciPy; отдельный локальный HTTP-сервис EASE с предобученной матрицей. На стороне Node.js также есть SVD-рекомендатель и эвристические резервные варианты. |
| Векторный поиск | Qdrant по REST, LlamaIndex/Qdrant-клиент и локальная модель `Xenova/multilingual-e5-small` через `@xenova/transformers` (векторы размерности 384). |
| Генеративный ИИ | Yandex Foundation Models API, модель `yandexgpt-lite`; сервер обращается к ней по HTTP. |
| Постеры | Yandex Cloud Object Storage через AWS SDK for JavaScript (S3-совместимый API), подписанные ссылки; возможно использование обычного `posterUrl` из БД. |

`chromadb`, `connect-pg-simple` и некоторые другие пакеты присутствуют в зависимостях, но само наличие пакета не означает его использование в основном потоке приложения. Основная векторная БД в текущем коде — Qdrant, а хранилище HTTP-сессий по умолчанию — память процесса.

## 3. Общая архитектура и потоки данных

```text
Браузер (React SPA)
    │ fetch /api/*, cookie сессии
    ▼
Node.js / Express (один публичный HTTP-сервер)
    ├── Passport + express-session ── PostgreSQL (пользователи)
    ├── API + DatabaseStorage ─────── PostgreSQL (фильмы, оценки, списки)
    ├── поиск по смыслу ───────────── локальные E5-эмбеддинги ── Qdrant
    ├── рекомендации ──────────────── HTTP ── Python/FastAPI EASE
    │                                  └── SVD / жанровый / популярный fallback
    ├── объяснения и переранжирование ─ HTTPS ─ YandexGPT
    └── URL постеров ───────────────── S3 API ─ Yandex Object Storage
```

Браузер работает с сервером через относительные URL `/api/*`; прямых вызовов Qdrant, YandexGPT, PostgreSQL или S3 с фронтенда нет. `server/index.ts` запускает дочерний процесс Python-сервиса и основной Express-сервер (обычно порт 5000). В режиме разработки Vite обслуживает клиент через Express; production-сборка собирает клиент и Node-сервер, копируя файлы Python-сервиса. Для работы EASE необходимы файлы предобученной модели и соответствующие Python-зависимости.

### Поиск

`POST /api/search` принимает `query`, `genres`, опционально `minYear`, `maxYear`, `minRating`, `searchMode` и `debug`:

1. По умолчанию сервер вычисляет эмбеддинг запроса, ищет подходящие `fid` в Qdrant и сопоставляет их с фильмами PostgreSQL. Если векторный поиск завершился ошибкой, используется SQL-поиск по названию.
2. В явном режиме `text` выполняется поиск по названию в PostgreSQL; без текста возвращаются фильмы по числу оценок с учётом жанра.
3. Результаты фильтруются и ограничиваются десятью фильмами. При наличии YandexGPT и семантического режима сервер может создать объяснения для фильмов, заново отсортировать результаты LLM и сформировать общее резюме.
4. В JSON-ответе приходят `movies`, `summary`, `query`, `searchMethod` и, если запрошено, `diagnostics`.

Векторы служат поисковым индексом, а карточки фильмов и их атрибуты берутся из PostgreSQL. Настройка подключения к Qdrant задаётся через `QDRANT_HOST`; значение по умолчанию в коде — `http://localhost:6333`. Не следует считать указанный в старых заметках внешний IP текущим адресом работающего сервера без отдельной проверки. Имя коллекции по умолчанию — `movie_embeddings`; часть Qdrant-кода допускает `QDRANT_COLLECTION`, а прямой клиент использует фиксированное имя коллекции.

### Рекомендации

- **Гость:** QuickRating собирает оценки локально и отправляет их на `POST /api/recommendations/anonymous`. Сервер вызывает EASE для подбора ещё не оценённых фильмов; если предсказаний нет, возвращает популярные. При доступности YandexGPT добавляется общее объяснение списка. Результат возвращается клиенту, но не сохраняется в таблицу рекомендаций.
- **Вошедший пользователь:** `GET /api/recommendations/personalized` загружает сохранённые оценки из PostgreSQL. Без оценок выдаёт популярные фильмы; иначе пробует EASE, затем SVD, затем жанровое ранжирование. Персональные объяснения для фильмов формируются опционально через YandexGPT.
- **Важное ограничение:** персональный маршрут сопоставляет предсказания EASE только с первыми 50 фильмами, загруженными сервером для этого запроса. Поэтому часть предсказанных идентификаторов может отбрасываться и срабатывать резервный алгоритм.

Python-сервис читает файлы модели из `attached_assets/EASE/`, предоставляет `GET /health`, `POST /predict` и `GET /movies/{fid}/exists`. Основной сервер запускает его на `EASE_PORT` (по умолчанию **6334**), но Node-клиент без `EASE_SERVICE_URL` обращается к **6333**. Это расхождение конфигурации: для обращения к запущенному дочернему сервису нужно явно задать `EASE_SERVICE_URL=http://localhost:6334` либо исправить значение по умолчанию в коде. Порт 6333 также используется Qdrant по умолчанию, но это другой сервис.

### Постеры

Сервис постеров выбирает источник в следующем порядке: уже записанный в PostgreSQL `posterUrl` → S3 (если у фильма есть `s3PosterKey`) → изображение-заглушка от `placehold.co`. Для объекта в S3 сервер проверяет наличие `${fid}.jpg` и создаёт подписанный URL сроком до часа; кэш таких URL в памяти живёт 55 минут. В ответе API поле `posterUrl` заменяется выбранным URL. Прямой интеграции с API TMDB или маршрута загрузки постеров в текущем сервере нет. `kinopoiskUrl` — ссылка на внешний сайт, а не запрос к API Кинопоиска.

## 4. Хранилища данных

### PostgreSQL — основной источник данных

`shared/schema.ts` определяет таблицы:

| Таблица | Содержание |
|---|---|
| `users` | Логин (уникальный), хеш пароля, отображаемое имя, аватар. |
| `movies` | Первичный ключ `fid`, названия, год, жанры, описание, участники, рейтинг/число голосов, ссылки на постер, S3-ключ и другие метаданные. |
| `ratings` | Оценка пользователя для фильма (1–10), необязательный отзыв, время создания. |
| `watchlist`, `favorites` | Связь пользователя с отложенными и избранными фильмами. |
| `recommendations` | Схема для сохранённых рекомендаций (`score`, `source`, `explanation`), но текущие маршруты формируют ответы на лету и не сохраняют их сюда. |

Связи с пользователями/фильмами заданы внешними ключами. Для пар (`userId`, `movieId`) в таблицах оценок и списков в схеме не заданы уникальные ограничения; предотвращение повторов и обновление оценок в основном реализованы прикладным кодом. `DatabaseStorage` в `server/storage.ts` инкапсулирует запросы каталога, поиск по названию, оценки, профиль и списки.

### Другие данные

- **Qdrant:** индекс эмбеддингов фильмов для семантического поиска и поиска похожих фильмов; основной текст и пользовательские данные хранятся не здесь. В репозитории нельзя надёжно подтвердить актуальное число объектов во внешней коллекции.
- **EASE:** предобученная матрица и отображение ID фильмов в файлах `attached_assets/EASE/`, загружаемые Python-процессом при запуске; это не SQL-база.
- **Yandex Object Storage:** файлы постеров, доступные серверу через S3-совместимый API; постоянные ссылки/ключи описаны в `movies`.
- **`localStorage` браузера:** временные анонимные оценки QuickRating (24 часа).
- **Память процесса Node.js:** HTTP-сессии `express-session` по умолчанию и кэш подписанных URL постеров. Несмотря на установленный `connect-pg-simple`, PostgreSQL-хранилище сессий не подключено.

## 5. Внешние интеграции и конфигурация

| Сервис | Способ обращения | Настройка / статус |
|---|---|---|
| Yandex Foundation Models | HTTPS API генерации текста; объяснения, сводка, LLM-переранжирование | `YANDEX_API_KEY`, `YANDEX_CATALOG_ID`; клиент создаётся только при наличии обоих параметров. |
| Yandex Cloud Object Storage | S3-совместимый API `storage.yandexcloud.net`, регион `ru-central1` | `YANDEX_S3_ACCESS_KEY_ID`, `YANDEX_S3_SECRET_ACCESS_KEY`; `YANDEX_S3_BUCKET` необязателен (по умолчанию `cinefeels-movies`). |
| Qdrant | REST API внешнего или локального векторного сервера | `QDRANT_HOST` (по умолчанию localhost:6333), частично `QDRANT_COLLECTION`; доступность зависит от реально запущенного сервиса. |
| Python EASE | Внутренний HTTP API на локальном порту, запускается Node-процессом | `EASE_PORT` для Python, `EASE_SERVICE_URL` для Node-клиента; их значения по умолчанию **не совпадают**. |
| Кинопоиск / `placehold.co` | Внешняя ссылка из карточки / URL заглушки для изображения | Не интеграция с API; запросы к картинке выполняет браузер. |

Также требуется `DATABASE_URL` для PostgreSQL и следует настроить `SESSION_SECRET` для сессий. Значения ключей и строк подключения в документации не приводятся. Конфигурация задаёт, куда обращаться; наличие переменной само по себе не подтверждает доступность сервиса.

## 6. Основные маршруты API

| Область | Маршруты | Доступ |
|---|---|---|
| Вход и сессия | `POST /api/auth/register`, `/api/auth/login`, `/api/auth/logout`; `GET /api/auth/me` | Публичные; `me` возвращает `null` гостю. |
| Каталог | `GET /api/movies`, `/api/movies/featured`, `/api/movies/popular`, `/api/movies/recent`, `/api/movies/for-rating`, `/api/movies/:id`, `/api/movies/:id/similar`; `GET /api/genres`, `/api/genres/count`, `/api/genres/top` | Публичные. |
| Поиск | `POST /api/search` | Публичный. |
| Оценки и профиль | `POST /api/ratings`; `GET /api/users/profile` | Требуется вход. Отдельного `GET /api/ratings` в текущем коде нет; оценки доступны в профиле/карточках. |
| Рекомендации | `GET /api/recommendations/personalized`; `POST /api/recommendations/anonymous`; `GET /api/ease/health` | Персональный маршрут допускает гостя, но возвращает ему популярные фильмы; два остальных публичные. |
| Списки | `GET /api/watchlist`, `/api/favorites`; `POST` и `DELETE /api/watchlist/:movieId`, `/api/favorites/:movieId` | Требуется вход. |
| Постеры и обслуживание | `GET /api/posters/:fid`; `POST /api/admin/update-embedding/:fid` | Сейчас оба маршрута публичны, включая обновление эмбеддинга. |

## 7. Границы реализации и эксплуатационные замечания

- **Критичная конфигурационная ошибка:** EASE запускается по умолчанию на 6334, а клиент обращается на 6333. Пока адреса не согласованы, рекомендации переходят на резервные варианты, а `/api/ease/health` сообщает недоступность EASE.
- **Безопасность:** административный маршрут изменения эмбеддинга не защищён аутентификацией; `SESSION_SECRET` имеет небезопасное значение по умолчанию. Сессии в памяти процесса теряются после перезапуска и не подходят для нескольких реплик без общего хранилища.
- **Интерфейс:** неверный `/api/user` на главной мешает показать блок персональных рекомендаций; в поиске не подключено переключение текстового режима. Эти проблемы описаны как текущее состояние, а не как реализованные функции.
- **Не обещаются:** конкретное время ответа AI, число фильмов/векторов в удалённом Qdrant, конкретный поставщик PostgreSQL или готовность к production — это зависит от окружения и не подтверждается одним только исходным кодом.

Ориентиры в коде: `client/src/App.tsx` и `client/src/pages/` (UI), `server/routes.ts` (API), `server/auth.ts` (сессии), `server/storage.ts` и `shared/schema.ts` (данные), `server/ease_service/` и `server/ease-client.ts` (EASE), `server/ai/` и `server/qdrant-store.ts` (поиск), `server/yandexgpt.ts` (LLM), `server/poster-service.ts` и `server/s3-client.ts` (постеры), `server/index.ts` (запуск).
