# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## MediaVibe: Портал рекомендаций фильмов с гибридной системой RAG и матричной факторизацией

***

## 1. ОБЩАЯ ИНФОРМАЦИЯ

### 1.1 Описание проекта

**MediaVibe** — веб-приложение для персонализированных рекомендаций кинофильмов, построенное на гибридной архитектуре, объединяющей две независимые системы рекомендаций через единый LLM-интерпретатор.

**Основной концепт:**
- **Матричная факторизация**: анализирует исторические рейтинги пользователей и извлекает скрытые паттерны предпочтений
- **RAG-система**: обрабатывает свободные текстовые запросы пользователей, извлекая релевантные фильмы из базы знаний
- **LLM-интерпретатор**: генерирует персонализированные объяснения для обеих систем в человекочитаемом формате

### 1.2 Платформа и окружение

- **Платформа**: Replit
- **Развёртывание**: облачное, без необходимости локальной конфигурации
- **Язык бэкенда**: Python (Flask/FastAPI)
- **Фронтенд**: React/Vue.js или ванильный JavaScript + HTML/CSS
- **Основные зависимости**: scikit-learn (матричная факторизация), LangChain/llamaindex (RAG), API LLM (OpenAI/Anthropic/Local)

### 2.2 Поток данных

**Сценарий 1 (Персональная лента — матричная факторизация):**
```
Пользователь открывает профиль
    ↓
Загружаются его рейтинги из БД
    ↓
Матричная факторизация вычисляет embeddings (SVD/NMF)
    ↓
Выбираются топ-N фильмов по скрытым факторам
    ↓
Передаются LLM с контекстом истории просмотров
    ↓
LLM генерирует объяснения (почему эти фильмы подходят)
    ↓
Результаты отправляются на фронтенд
```

**Сценарий 2 (Поиск по запросу — RAG):**
```
Пользователь вводит текстовый запрос ("Комедия про офис")
    ↓
Текст кодируется в vector embedding
    ↓
RAG-система (semantic search) извлекает релевантные фильмы
    ↓
Передаются LLM с исходным запросом
    ↓
LLM генерирует объяснения соответствия
    ↓
Результаты отправляются на фронтенд
```

### 3.2 Бэкенд: Матричная факторизация

#### 3.2.1 Архитектура

```python
class MatrixFactorizationEngine:
    """
    Система рекомендаций на основе матричной факторизации.
    
    Входные данные:
    - user_id: ID пользователя
    - rating_matrix: разреженная матрица (users × movies)
    
    Процесс:
    1. SVD/NMF разложение матрицы рейтингов
    2. Вычисление user embeddings и movie embeddings
    3. Вычисление скрытых факторов сходства
    4. Ранжирование фильмов по предсказанному рейтингу
    
    Выходные данные:
    - top_n_recommendations: список (movie_id, predicted_score, similarity_factors)
    """
```

#### 3.2.2 Алгоритм

- **Метод**: SVD (Singular Value Decomposition) или NMF (Non-negative Matrix Factorization)
- **Библиотека**: scikit-learn (`TruncatedSVD`, `NMF`)
- **Ранжирование**: predscore = user_embedding · movie_embedding
- **Фильтрация**: исключение уже оценённых фильмов
- **Кэширование**: сохранение embeddings для избежания переперечислений

#### 3.2.3 Особенности

- **Масштабируемость**: для 10K+ пользователей требуется инкрементальное обновление
- **Холодный старт**: для новых пользователей используется наивный baseline (популярные фильмы)
- **Объяснимость**: сохранение факторов сходства для передачи LLM

### 3.3 Бэкенд: RAG-система

#### 3.3.1 Архитектура

```python
class RAGRecommendationEngine:
    """
    Система рекомендаций на основе Retrieval-Augmented Generation.
    
    Входные данные:
    - query: текстовый запрос пользователя ("Комедия про офис")
    - knowledge_base: документы (синопсисы, теги, рецензии)
    
    Процесс:
    1. Кодирование query в embedding
    2. Semantic search в knowledge_base (косинусное сходство)
    3. Ранжирование результатов
    4. Передача топ-K документов в LLM контекст
    
    Выходные данные:
    - retrieved_docs: список релевантных фильмов
    - context_for_llm: метаданные для объяснений
    """
```

#### 3.3.2 Компоненты

| Компонент | Описание | Реализация |
|-----------|---------|-----------|
| **Retriever** | Семантический поиск | Embedding модель (SentenceTransformer или API), FAISS/Chroma индекс |
| **Ranker** | Ранжирование результатов | BM25 + semantic similarity гибрид |
| **Knowledge Base** | База данных о фильмах | Синопсисы, теги, отзывы, жанры в структурированном формате |
| **Context Builder** | Подготовка контекста | Форматирование документов для LLM промпта |

#### 3.3.3 Особенности

- **Embedding модель**: использовать многоязычную модель (например, `intfloat/multilingual-e5-large` для русского)
- **Индексирование**: FAISS или Chroma для быстрого поиска
- **Обновление KB**: incrementally добавлять новые фильмы
- **Фильтрация**: опция фильтрации по жанру, году, рейтингу

### 3.4 Бэкенд: LLM-интерпретатор

#### 3.4.1 Назначение

LLM генерирует естественноязычные объяснения для рекомендаций из обеих систем.

#### 3.4.2 Процесс

**Для матричной факторизации:**
```
Входные данные:
- user_id, user_history (фильмы, которые пользователь смотрел)
- recommended_movies (топ-N с предсказанными рейтингами)
- similarity_factors (скрытые факторы сходства)

Промпт:
"""
Пользователь смотрел фильмы: {user_history}
Мы рекомендуем ему эти фильмы:
{recommended_movies}

Факторы сходства (на уровне embeddings):
- Фильм A близок по скрытому фактору "драма + психология"
- Фильм B имеет схожий паттерн предпочтений пользователя

Сгенерируй персонализированное объяснение, почему именно эти фильмы подходят.
Формат: короткий абзац (2-3 предложения) для каждого фильма.
"""

Выходные данные:
- explanation: "Этот фильм рекомендуется, потому что вы любите 
  психологические драмы с тёмным юмором (как в фильмах X и Y), 
  а этот фильм имеет похожие мотивы."
```

**Для RAG:**
```
Входные данные:
- query: "Комедия про офис с острым юмором"
- retrieved_docs: [Синопсис A, Синопсис B, Синопсис C]

Промпт:
"""
Запрос пользователя: {query}
Найденные фильмы:
{retrieved_docs}

Объясни, как каждый найденный фильм соответствует запросу.
Укажи конкретные элементы (сцены, персонажи, стиль юмора),
которые связывают фильм с запросом.
"""

Выходные данные:
- explanation: "В этом фильме острый офисный юмор проявляется через...
  (конкретные примеры). Это соответствует вашему запросу тем, что..."
```

#### 3.4.3 Параметры LLM

- **Модель**: GPT-4, Claude 3, или локальная (Mistral, LLaMA)
- **Температура**: 0.7 (баланс между креативностью и консистентностью)
- **Max tokens**: 150–200 на объяснение
- **Language**: русский
- **API**: OpenAI, Anthropic, или локальный сервер (для Replit можно использовать локальный small LLM)

#### 3.4.4 Промпт-инжиниринг

- **System prompt**: определить роль LLM (кинокритик-рекомендатель)
- **Few-shot examples**: включить 2–3 примера хороших объяснений
- **Constraints**: избежать спойлеров, максимум 3 предложения

## 4. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 4.1 Производительность

| Метрика | Целевое значение |
|---------|-----------------|
| Время загрузки профиля | < 1.5 с |
| Время генерации рекомендаций (MF) | < 2 с (кэшировано), < 5 с (fresh) |
| Время поиска (RAG) | < 3 с (включая LLM) |
| Время объяснения LLM | < 2 с (streaming опционально) |
| Throughput API | ≥ 100 req/sec |

### 4.2 Масштабируемость

- **Пользователи**: поддержка 10K+ активных пользователей
- **Фильмы**: 5K–50K фильмов в базе
- **Рейтинги**: 1M+ рейтингов в историческом буфере

- **Availability**: 99.5% uptime
- **Error handling**: graceful degradation (fallback на популярные фильмы при сбое MF)

- **Аутентификация**: JWT токены с 24h expiry

- **Input validation**: санитизация всех пользовательских входов
- **Rate limiting**: 100 req/min на пользователя
- **LLM API**: API ключи хранятся в environment переменных

### 4.5 Maintainability

- **Код**: Python PEP 8, типизация (type hints), docstrings
- **Версионирование**: Git с clear commit messages
- **Документация**: API docs (Swagger), README, архитектурная диаграмма

## 6. ДАННЫЕ И БД

### 6.1 Схема БД

#### Users
```sql
CREATE TABLE users (
  user_id UUID PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  INDEX(email)
);
```

#### Movies
```sql
CREATE TABLE movies (
  movie_id SERIAL PRIMARY KEY,
  title VARCHAR(512) NOT NULL,
  year INT,
  synopsis TEXT,
  genres VARCHAR(255)[],
  tags VARCHAR(255)[],
  poster_url TEXT,
  imdb_id VARCHAR(50),
  created_at TIMESTAMP DEFAULT NOW(),
  INDEX(title),
  INDEX(year)
);
```

#### Ratings
```sql
CREATE TABLE ratings (
  rating_id SERIAL PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  movie_id INT NOT NULL REFERENCES movies(movie_id) ON DELETE CASCADE,
  rating FLOAT CHECK (rating >= 1 AND rating <= 5),
  review TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, movie_id),
  INDEX(user_id, movie_id)
);
```

#### MovieEmbeddings (кэш для RAG)
```sql
CREATE TABLE movie_embeddings (
  embedding_id SERIAL PRIMARY KEY,
  movie_id INT NOT NULL REFERENCES movies(movie_id) ON DELETE CASCADE,
  embedding FLOAT8[] (384),  -- для sentence-transformers
  embedding_model VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(movie_id, embedding_model)
);
```

#### MFEmbeddings (кэш для матричной факторизации)
```sql
CREATE TABLE mf_embeddings (
  mf_id SERIAL PRIMARY KEY,
  user_id UUID REFERENCES users(user_id) ON DELETE CASCADE,
  movie_id INT REFERENCES movies(movie_id) ON DELETE CASCADE,
  user_embedding FLOAT8[] (50),    -- латентные факторы
  movie_embedding FLOAT8[] (50),
  mf_model_version VARCHAR(50),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, movie_id, mf_model_version)
);
```

### 6.2 Инициализация данных

- **Источник фильмов**: Kinopoisk API, IMDb dataset, или public movie DB
- **Количество**: минимум 1K фильмов для MVP
- **Синопсисы**: текстовые описания для RAG
- **Жанры/теги**: категоризация для фильтрации

### 6.3 Кэширование

- **Redis**: кэш рекомендаций на 1 час
- **In-memory**: FAISS индекс (загружается при старте)
- **TTL**: 6 часов для embeddings

## 9. РИСКИ И МИТИГАЦИЯ

| Риск | Вероятность | Влияние | Митигация |
|------|------------|--------|----------|
| LLM API лимиты/затраты | Высокая | Высокое | Кэширование объяснений, использование локальной модели, rate limiting |
| Холодный старт (новые пользователи) | Средняя | Среднее | Baseline рекомендации (популярные фильмы), явный сбор предпочтений |
| Качество embeddings | Средняя | Высокое | Тестирование на validation set, fine-tuning при необходимости |
| Sparsity рейтингов (мало оценок) | Высокая | Среднее | Гибридный подход (контентный + коллаборативный), ensemble методы |
| Latency LLM вызовов | Средняя | Высокое | Async/await, streaming responses, кэширование |
| Replit лимиты (RAM, CPU, ограничения) | Средняя | Среднее | Профилирование, оптимизация, опция перехода на другую платформу |

## Приложение А: Примеры промптов

### A.1 Матричная факторизация — System Prompt

```
Ты — опытный кинокритик и рекомендатель фильмов.
Твоя задача — объяснить пользователю, почему конкретные фильмы ему подходят,
основываясь на его историй просмотров и предпочтениях.

Ключевые правила:
1. Говори на русском языке
2. Используй конкретные примеры из фильмов, которые пользователь смотрел
3. Не спойлерь сюжет
4. Будь энтузиастичен, но не преувеличивай
5. Объяснение должно быть 2–3 предложения максимум
```

### A.2 RAG — System Prompt

```
Ты — рекомендатель фильмов, специализирующийся на поиске кинематографии
по описаниям и настроениям.

Твоя задача — объяснить, почему найденные фильмы соответствуют запросу пользователя.

Ключевые правила:
1. Говори на русском языке
2. Укажи конкретные элементы фильма (жанр, тон, сюжетные элементы)
3. Чётко связывай объяснение с исходным запросом
4. Не спойлерь
5. Объяснение 2–3 предложения
```

### A.3 Пример Few-shot для MF

```
Пользователь смотрел: "Класс", "Подземелье драконов", "Матрица"

Рекомендуем: "Начало" (Inception)
Объяснение: "Как и в 'Матрице', здесь сложная научно-фантастическая концепция с головокружительными экшн-сценами. 'Начало' тоже требует включить голову, что соответствует вашему вкусу к интеллектуальным триллерам."

---

Пользователь смотрел: "Интерстеллар", "Край будущего", "За бортом"

Рекомендуем: "Синий идентификатор" (Blue Identification)
Объяснение: "Этот фильм делит c 'Интерстелларом' философские размышления о времени и сознании, а с 'За бортом' — лёгкий юмор в серьёзном контексте."
```
